`.mnemon/` 项目级记忆存储（2026-09-19 用户决定：归一化路径后提交，理由=记忆随项目走）。布局事实：**每个仓库各有自己的 `.mnemon/`**（onshapescript/taobao-mcp/dsh-bench 等同样存在），`~/.mnemon` 是全局库（含 `data/default/mnemon.db`），本会话读的是**项目级**那份。**文档存储是文件式、无 DB**：`.mnemon/documents/active/<slug>-<id8>.md` = YAML frontmatter + 正文，`documents/index.json` 是索引，**文件即权威**。**contentHash 算法已实测确认 = `sha256(正文.trim())`**，正文=frontmatter（`^---\n[\s\S]*?\n---\n`）之后的部分；frontmatter 的 `content_hash`、index.json 的 `contentHash` 两者必须同值，`sizeBytes` 是文件总字节，`index.json` 用 `JSON.stringify(obj,null,2)+"\n"` 序列化（字节可复现，可直接重写）。**归一化硬规则**：`.mnemon/` 内不得出现操作者的家目录绝对路径或用户名，改用「本仓库」「本地开发者」；注意**描述这条规则的文字本身也会被扫到**，别在记忆里写出该路径字面量。运行时文件 `runtime/{memories.json,MEMORY.md,USER.md}` **每次记忆写入都会被运行时改写**（提交后会持续漂移，属预期，非 bug）；`documents/` 不会被自动改写，故手改安全。`memories.json` 条目带 `branches:["main"]`，只在 main 分支注入。
