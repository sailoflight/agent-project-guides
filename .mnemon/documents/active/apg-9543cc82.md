# APG 入口化与组件复用：本机组件库上线，并对外部能力做了内部实测（4.0.0）

状态：**契约已上线（ADR 0009 + 0010），第一个真实实例已建成，外部能力的内部实测已做完并据此修掉两处真缺陷**；版本号已抬到 `4.0.0`（`d561a52`），**标签 `v4.0.0` 故意未打**。本文是派生件，不是权威源：权威顺序 `decisions/0010` → `decisions/0009` → `plans/MULTI_AGENT_INFRA_INTEGRATION_RESEARCH.md` §13.20 与 §13.21 → 仓内代码与门禁。

## 1. 用户方向（原话要点）

- 先让 APG 住进去，再由 APG 把别的东西带进来（入口化）。
- **有些东西不用部署第二遍（HTTP），这种找已经有的**。
- 提前在本机单独找个地方摆好文件包 + HTTP 服务器，组织方式参考 APG 的部署方式。
- **各项目都尽量使用现成的，别到处都是**；对两个开口的裁定是「**都做**」。
- 「新的版本可以变成 **4.0** 开头了」；「在正式推广测试前先内部喊几个 agents」；随后纠正：**「不是评审，是对外部能力做测试」**。

## 2. 契约（ADR 0009 D1–D7；D2 由 0010 细化、D7 由 0010 修订）

- **D1 落点** `<platformHomes(env).data>/components/`——`releases/` 的兄弟，沿用既有变量，不新增环境变量。
- **D2 引用** 项目只存引用；D2a（0010 新增）：`verify` 报 `packages`/`packages_total`/`reusable_packages`/`missing_packages`，`probe` 报 `probed`/`services`/`reusable_services`，**两个命令不得再发布同名裸 `reusable`**。
- **D3 两类条目** 包型 = `<id>/sha256-<hex>/` + 0444 canonical manifest（文件集须恰好相等）；服务型 = `services/<id>.json`，只记身份、不记字节。
- **D4 交付** `staged`（只验证/发现/复用，缺则 `not-installed`）／`fetched`（坐标供规程用，APG 不下载）；服务型只能是 `staged`。
- **D5 四态** `available`/`degraded`/`not-installed`/**`conflict`**；单例冲突 fail-closed，不替你挑。
- **D6 权限** 发现/校验/健康 = 只读；起停/重启/排空 = Operator + 确认 + 世代校验。
- **D7 分发面（已修订）** 校验与发现契约上分发面（`lib/components.mjs` + `schemas/component-entry.schema.json`，4.0.0 下 85 文件 / `sha256:9791c583…`）；采集器 `scripts/build-component-store.mjs` **不上**。
- **D8（0010 新增）服务条目的判据**：声明的 health 路径必须用**只读 GET** 返回该组件的 **identity**；端点必须**免凭据**可达；进程必须能被信号终止；`degraded` 永不算 `available`。

## 3. 第一个真实实例与版本记账

- 默认根 `~/.local/share/agent-project-guides/components`：9 件（`am`/`br`/`bv`/`cass`/`ee`/`ft`/`ntm`/`sbh`/`slb`）全部 `mode: link`（硬链接：同 inode、links=2，287.5 MiB 未复制第二份），全部 `available`，第二次运行 `materialised 0 / present 9`。**没有任何服务条目**（`services/` 目录不存在，`probe` 报 `probed: 0`）。
- 4.0.0 四处一起动：`PACKAGE_VERSION`、`.agent-project-guides.json` 的 `provider.release`、根块（`reattest` 重盖章，integrity `24366bf1…`）、`PACKAGE_MANIFEST.json`（85 文件 / `9791c583…`）。`project_digest` 随档案前移（`docs/memory` 的 18 条历史锚因此变旧，这是记忆锚拆分接受的语义，一条记录都没重写）。
- `CHANGELOG.md` 的 `## 4.0.0` 段接管了原先误挂在 `## 3.0.10` 名下的四个块；`## 3.0.10` 已逐字节还原为标签 v3.0.10 所钉的内容（用 `git show v3.0.10` 逐行 diff 验证）。

## 4. 对外部能力的内部实测（三个 agent，只读优先）

团队 `apg-4.0.0-external-capability-test`，三个成员：`cli-probe`（6 个 CLI 件）、`service-probe`（am/ee/ft）、`mcp-probe`（Bridge 控制面）。证据在 `.agent-scratch/capability-test-4.0.0/`（已忽略），摘要见 plan §13.21.3。captain 复核：无残留进程、端口全 free、工作树无新增改动。

- **CLI：6/6 可执行，sha256 与采集记录逐位一致。** 缺的不是本地可执行性，而是外部上下文（`br`/`bv` 要 `.beads`、`cass` 要 API key、`ntm` 要 tmux、`sbh` 真回收要 daemon+root，**`sbh` 核心功能完全未验证**）。两条副作用：`slb check` 会写 `.slb/state.db`（**不是只读**，要用必须 `--db`/`-C` 指临时目录）；`cm ls` 会自动建空 playbook。
- **服务：「不用部署第二遍」在真机成立，但只有 `am` 干净。** `am` 有 `serve-http`（MCP over streamable HTTP），实测在 `127.0.0.1:18765` 起来，`/healthz`→`{"status":"alive"}`、`/health`→`{"status":"ready","version":"0.3.36"}`；`ee` 的 `ee serve` 是真只读适配器但要 `--foreground` + ≥256bit token；`ft` 能起但 degraded（缺 WezTerm mux），`/metrics` 合法 Prometheus 却只是 metrics。**按 D8，三件都不够格做 service 条目**（`am` 的 GET 拿不到 identity，identity 只在 MCP 握手里）。
- **MCP：控制面活着，产品面在本会话不可达。** 本会话只有 `win-wsl-bridge-control` 的两个工具；`status` 显示 onshape/taobao 均 `running`/`mode:shared`（ownedGeneration 12 / 2，activeClients 各 2），但 `ownedGeneration`/`activeClients` 只是「已登记服务在跑且被共用」的**弱证据**，不能证明产品面可用、不能替代 store 的 identity+health 探针、不能排除 registry 外的第二份实例。
- **三条坑**：① 本环境 `http_proxy=127.0.0.1:10808` 且 curl 不认 `no_proxy` 里的 `127.*`，回环探测必须 `curl --noproxy '*'`，否则死服务返回 503 被读成活的（APG 自己走 `node:http`，不受影响）；② `ft watch` 收 SIGTERM 后不退出、且 `.ft/watch.lock` 挡住第二实例，只能 `kill -9`；③ `ft` 首次启动会往 `~/.local/share/fonts` 装 4 个 Nerd Font——**跑外部组件本身就可能改宿主**。

## 5. 实测改掉的两处真缺陷（4.0.0 打标签之前，提交 `878f8d9`）

1. **`verify`/`probe` 曾各自发布同名的裸 `reusable`，指的是两个域**：读 `probe` 的 `reusable: []`（只可能来自服务）会得出「没有任何可复用组件」，而同一次 `verify` 报 9 个包全 `available`。现各报自己的域，且 `probe` 聚合里恒为 `'none'` 的 `action` 已删。
2. **「200 但没有身份」曾报成 `the endpoint belongs to undefined`**（关于代码而不是关于组件的句子）。现在判 `conflict`，理由点名缺什么：`the health response carries no component identity`。**liveness 不是 identity**——这正是四状态词表要防的误复用。

门禁 `scripts/test-component-store.mjs` 从 55 条增到 **64 条 / 12 组**（新增「两个命令各报自己的域」与「liveness 不是 identity」）；**反证已跑**：把 identity 分支改回原样，门禁红在 `actual: 'the endpoint belongs to undefined'`。整轮 `scripts/test-release.sh` exit 0，boundary `10 groups, 85 files`，writers `69/0/1`。

## 6. 仍未做（明确留给主人）

- **service 条目仍然是 0 条。** 契约缺口不在组件而在记录形状：`probeService` 只认 health JSON 里的 `id`/`revision`，**记录里没有办法声明别的字段名**，所以「自己用别的字段名声明身份」的服务永远到不了 `available`。要不要让 service 条目声明 identity 映射（乃至允许一次只读握手），是**契约决定**，ADR 0010 D8 只写判据、没有替主人选实现。
- **标签 `v4.0.0` 未打**（一条命令的事），等内部实测之后、推广空跑通过再打。
- **消费者铺开未做**：12 个真实消费者仓一个都没碰。
