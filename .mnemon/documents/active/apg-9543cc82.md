# APG 入口化与组件复用：本机组件库上线（ADR 0009 + ADR 0010）

状态：**已定案并全部落地**。契约由 `decisions/0009` 定义、`decisions/0010` 把"校验与发现"契约放上分发面并开出第一个真实实例；两个待定问题（决策 2、第一个真实实例）**已由主人一句「都做」打开并做完**。**派生件，不是权威源**：权威顺序 `decisions/0010` → `decisions/0009` → `plans/MULTI_AGENT_INFRA_INTEGRATION_RESEARCH.md` §13.20 与 §10 → 仓内代码与门禁；冲突以仓内为准。

## 1. 用户方向（原话要点，2026-09-20）

- 先让 APG 住进去，再由 APG 把别的东西带进来（入口化）。
- **有些东西不用部署第二遍（HTTP），这种找已经有的**。
- 提前在本机单独找个地方摆好文件包 + HTTP 服务器，组织方式**参考 APG 的部署方式**。
- **各项目都尽量使用现成的，别到处都是**。
- 对两个开口的裁定：「**都做**」。

前提同 plan §10.1（"WSL 里服务走 HTTP 直接接"），§10.2 判定"成立且更省事……ACFS 可整段跳过"。

## 2. 定案内容（D1–D7，D7 由 ADR 0010 修订）

| 决定 | 内容 |
|---|---|
| D1 store 落点 | `<platformHomes(env).data>/components/`——即 `thin-bootstrap` 已在用的机器包 store 的**同级**（`releases/` 旁），沿用 `AGENT_PROJECT_GUIDES_HOME` / XDG / Windows **既有**规则，**不新增环境变量** |
| D2 | 项目只存引用（包型 `id@version`、服务型服务身份）；descriptor、根块、每轮注入面均不变 |
| D3 两类条目 | **包型**：`<components>/<id>/sha256-<hex>/` + 只读（0444）canonical manifest，文件集须**恰好相等**、manifest **不属于自身内容集**；**服务型**：`services/<id>.json` 只记身份（endpoint/transport/revision/health/singleton），**不记字节** |
| D4 交付语义 | `staged`（须已就位；APG 只验证+发现+复用，缺则 `not-installed` 且不代下载）／`fetched`（按记录坐标由规程获取）。**服务型只能是 `staged`** |
| D5 四态发现 | `available`／`degraded`／`not-installed`／**`conflict`**；`conflict` 同时覆盖"端口上是别的东西"与"单例存在第二个实例"，**单例冲突 fail-closed，不替你挑一个**（挑一个等于悄悄恢复第二份部署） |
| D6 权限 | 发现/校验/健康 = 只读（Production/User）；起停/重启/排空 = Production/Operator，且需确认与世代校验（对齐 `profiles/mcp/WINDOWS_WSL_BRIDGE.md`） |
| D7（**已修订**） | 原：不进分发面。ADR 0010 改为：**校验与发现契约进分发面**（`lib/components.mjs` + `schemas/component-entry.schema.json`），**采集路径仍不进**（`scripts/build-component-store.mjs` 保持非分发） |

## 3. 落地与验证（含 ADR 0010 之后的状态）

- 契约：`decisions/0009-local-component-store.md` 与 `decisions/0010-component-store-on-the-distribution-surface.md`（均非分发）。
- 分发面：83 → **85** 个文件（新增上述两件），摘要 `sha256:148974e8…` → **`sha256:293959867428afd08fea66b5e878c81a1afde5d94c939eefaf71e656a40d344f`**；`catalog check`（253 条）、`release verify-source`、`project validate` 全 `valid`。
- CLI：`apg components verify|probe`，只读；store 不存在返回 `present:false` 且**不是错误**；`probe` 只发一条 `GET` 到声明的 health 路径。组名用 `components` 而非 `store`——`scripts/test-boundary.mjs:33` 的 `FORBIDDEN` 明确拒绝指称机制的名字。
- 强制点 `scripts/test-component-store.mjs`（**55 条断言**，已接进 `scripts/test-release.sh`）：import **已发货的** `lib/components.mjs`（旧版自带私有校验器、41 条断言）；新增 schema 与代码字段互相对齐；用真实 127.0.0.1 服务验证四态；断言探测只发已声明的只读请求。**反证已跑**：注释掉文件集比较那行 → 门禁红；恢复 → 绿。
- 第一个真实实例：默认根 `/home/lijq/.local/share/agent-project-guides/components`，9 件（`am`/`br`/`bv`/`cass`/`ee`/`ft`/`ntm`/`sbh`/`slb`）全部 `mode: link`（硬链接，287.5 MiB 未复制第二份），全部 `available`，第二次运行 `materialised 0 / present 9`（幂等）。`--dry-run` 不写一个字节。**没有写服务条目**：这台机器上没有一个组件同时给出可核对 identity 与只读 health 端点，硬写等于编端点（`bridge_control status` 只给 id 与 generation，走自己的协议）。
- 门禁在编写期抓出的真缺陷（累计）：键名规则被 `"kind":"file"` 这个**值**撞上（改为判**键**，判别名改 `package`）；`verifyEntry` 先读文件、后比文件集（改为先比集合再验哈希）。

## 4. 仍未做（有理由，不是遗漏）

- **消费者铺开**：12 个真实消费者仓一个都未触碰；ADR 0010 只让能力可得，不等于采用。
- **版本号**：`main` 分发面（85）已超过标签 `v3.0.10` 钉的那份（83），`PACKAGE_VERSION` 仍 `3.0.10`；`3.0.10` 的权威是**标签**，下次发布**必须先**升版本。
- **服务条目**：等一个自己声明身份与 health 路径的本机服务。
- **储藏库生命周期**：不自愈、不清理；条目坏了报 `component_corrupt`，删除是人的动作。

## 5. 相关事实（供后续引用）

- 部署模式三支：`thin-bootstrap`（通用字节在机器包 store）／`embedded-local`（字节在项目内 `.agent-project-guides/local/releases/<sha256-hex>/`，其 Git 排除由 materializer 写出的 `.gitignore`（内容 `local/`）拥有，`lib/materializer.mjs:138`）／`source-worktree`（自托管，不经 materializer，故无那层排除）。
- 目录命名 `sha256-<hex>`；**机器路径与通用包字节不进 descriptor**（`docs/V2_CONTRACT.md:32`）。
- 入口化形态：进来的东西以**独立嵌套仓**住在 `plugins/<harness>-apg/`（`scripts/apg.mjs`、`.gitignore` 的 `/plugins/*/`），不是把字节塞进 APG 分发面。
- 采集记录 `scripts/external-components.json`（9 件发布件 + 2 个源码检出，非分发）；第一条真实服务条目的判据见 ADR 0010 D6。
