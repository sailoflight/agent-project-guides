## 1. 用户方向（2026-09-20，原话要点）

- 能不能**先让 APG 住进去，然后 APG 把别的东西带进来**。
- **有些东西不用部署第二遍（HTTP）**，"这种找已经有的"。
- **尽量复用现有的**；用户会**提前在本机单独找个地方摆好文件包 + HTTP 服务器**，并要求其组织方式**参考 APG 的部署方式**。
- 同类前提此前已记在 plan §10.1（②"WSL 里服务走 HTTP 直接接，本地部署"）；§10.2 判定"成立且更省事……ACFS 可整段跳过"。

## 2. 边界：APG 不"带"基础设施，而是控制面

- 架构 A（Full Stack：自实现任务/消息/锁/生命周期/调度）**Reject**；选定**架构 B 控制面** + 让步档位 1。让掉：任务/依赖（`br`）、消息（Mail）、lifecycle/调度（NTM）、记忆检索（CASS/EE）、文件协调；保留：descriptor、角色语义、权威合成、证据/验收合同、项目记忆、context assembly。
- 因此"带进来"的正确形态是 **APG 当入口**：进来的东西以**独立嵌套仓**住在 `plugins/<harness>-apg/`。依据：`scripts/apg.mjs`（"harness-specific integrations belong in plugins/<harness>-apg/"）、`.gitignore` 的 `/plugins/*/`（"independent nested repositories, not APG source/gitlinks"）、`docs/V2_CONTRACT.md`（DSH adapter pending `plugins/dsh-apg`）。既有托管文档亦记 `plugins/dsh-apg/` 现状（只有 README/.gitignore + 真实子 `.git/`，父仓无 gitlink）。

## 3. 已核实的"APG 自身部署方式"（要被参考的就是这五条）

| # | 内容 | 依据 |
|---|---|---|
| 1 | 本机一个版本化目录，多版本共存 | `scripts/apg.mjs` 的 `release install` → `installRelease`；`lib/core.mjs` 的 `platformHomes` |
| 2 | 逐文件 sha256 清单 + 自摘要 `digest = sha256(canonicalJson(去掉 digest 的自己))` | `PACKAGE_MANIFEST.json`；`buildFileManifest` |
| 3 | **用前验证，验不过不加载** | `scripts/apg-launcher.mjs` 的 `validateRelease`：摘要须对上 descriptor、每文件 bytes+sha256 须匹配、路径安全（禁绝对路径/`\`/`..`/大小写撞车）、禁符号链接、**文件集必须恰好相等**（多一个文件即 fail）；文件头注释即 "No runtime imports are allowed before manifest verification" |
| 4 | 项目里只留薄壳 | descriptor 只记 `provider = { mode, release, digest }`，指向本机那份不可变副本；包内容不进项目 |
| 5 | 四分开 scope | `data`（内容/多版本）· `state`（clone-local 运行态）· `cache` · `bin`（launcher 壳） |

一句话：**内容寻址 + 用前验证 + 清单（事实）进 git、重件留本机**。

## 4. 映射：四条可照抄，HTTP 那条必须换判据

| APG 的方式 | 文件包（可照抄） | HTTP/服务型（换判据） |
|---|---|---|
| 版本化目录、多版本共存 | ✅ `packages/<id>/<version>/` | ❌ 不适用——"正在跑"无法被复制成一个目录；端口是独占资源，两个实例本身就是危害 |
| 逐文件 sha256 + 文件集恰好相等 | ✅ 现有校验器可原样复用 | ➖ 换成**握手 + revision + 能力面** |
| 用前验证 | ✅ | ✅ 语义保留，实现换成 **health + 握手**（连之前先问"你是谁、哪个 revision"） |
| 摘要即权威 | ✅ `sha256:…` | ➖ 换成**端点身份**：`host:port` + 协议 + revision（+ 可选 token） |
| 项目里只留指针 | ✅ 记 `id@version` | ✅ 记服务身份 |

## 5. 组件判据与状态

- **文件型**（`br`/`ntm`/`cass`/`ee` 等）：路径 + sha256 + `--version`；唯一性由文件系统天然给出。
- **服务型**（Mail 8765、CM、WSL facade / Windows engine）：端点 + 传输 + 握手/revision + health；**单例**，重复即 fail-closed。
- 状态沿用既有词表 `available / degraded / not-installed`（`decisions/0007`，非分发），并**新增 `conflict`**——"端口开着但不是它"必须能表达。**发现必须能证伪**：认不出就报 `degraded`/`conflict`，不得报 `available`。

## 6. scope 切分（易错点）

- **宿主/机器 scope**：store 本体、服务端点、上次发现结果（可重建，定位同"检索索引"）。
- **项目 scope（进 git、随 clone 走）**：只记"依赖哪个条目"+"上次见到的 revision"。
- 反例：12 个项目各缓存一份发现结果 ⇒ 同一服务 12 个答案、必然陈旧分叉。

## 7. 权限分层

- 发现/校验/健康探测：**只读**（Production / User 可做）。
- 起停/重启/回滚：**Operator**，需 `confirm` + 世代校验（范式见 `profiles/mcp/WINDOWS_WSL_BRIDGE.md` 的 Operator integration 行，以及环境里 bridge-control 的 `expectedGeneration`）。
- **复用连接 ≠ 有权动它**，两栏不得合并。

## 8. store 骨架（草案，命名可改）

```text
<store>/                    # 宿主 scope，永不进任何项目的 git
  store.json                # store 自身 schema/版本
  packages/<id>/<version>/  # 文件包本体（用户自取的字节）
  packages/<id>/<version>.manifest.json   # 逐文件 sha256 + 自摘要（照 APG 形状）
  services/<id>.json        # 端点 + 协议 + 期望 revision + singleton + 谁有权动它
  cache/services.json       # 上次发现结果（可重建）
```

落点**不写死**：照 `AGENT_PROJECT_GUIDES_HOME` 的现成做法由**环境变量指向**，这样既能摆 WSL 侧也能摆 Windows 侧——正好服务 `windows-wsl-bridge` 拓扑（`routing/mcp-subtypes.jsonl` 现有唯一子类型即它）。
