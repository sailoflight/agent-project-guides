状态：**契约已上线（ADR 0009 + 0010，D1–D12），第一个真实实例已建成并给出有信息的判决，外部能力内部实测已做完并据此修掉四处真缺陷，标签 `v4.0.0` 已打并推送**。版本 `4.0.0`：`d561a52` 抬版本、`a39c5a2` 补契约、`e6a7abf` 修路由、`8ef4855` 文档 rev 5、`ba3baeb` 写第一条服务条目＋采集规程（**标签指向此提交**，附注标签对象 `0fdcdf5`）、`657f74d` 记录打标签与「标签后只动非分发面」。本文是派生件，不是权威源：权威顺序 `decisions/0010` → `decisions/0009` → `plans/MULTI_AGENT_INFRA_INTEGRATION_RESEARCH.md` §13.20–§13.22 → 仓内代码与门禁。

## 1. 用户方向（原话要点）

- 先让 APG 住进去，再由 APG 把别的东西带进来（入口化）。
- **有些东西不用部署第二遍（HTTP），这种找已经有的**。
- 提前在本机单独找个地方摆好文件包 + HTTP 服务器，组织方式参考 APG 的部署方式。
- **各项目都尽量使用现成的，别到处都是**；对两个开口的裁定是「**都做**」。
- 「新的版本可以变成 **4.0** 开头了」；「在正式推广测试前先内部喊几个 agents」；随后纠正：**「不是评审，是对外部能力做测试」**。
- 「都修复一下，然后把**服务依赖的服务**也加入 APG 要求检查的东西，随后进一步处理，比较敏感的 root API 我自己来」。
- 追问「我需要配置什么」时明确：**「外部能力所需要的比较敏感的（配置）我自己来」**。

## 2. 契约（ADR 0009 D1–D7；0010 细化 D2/D7，新增 D2a、D5–D12）

- **D1 落点** `<platformHomes(env).data>/components/`——`releases/` 的兄弟，沿用既有变量，不新增环境变量。
- **D2/D2a 引用与输出域** 项目只存引用；`verify` 报 `packages`/`packages_total`/`reusable_packages`/`missing_packages`/`degraded_packages`/`conflicted_packages`，`probe` 报 `probed`/`services`/`reusable_services`，**两个命令不得再发布同名裸 `reusable`**。
- **D3 两类条目** 包型 = `<id>/sha256-<hex>/` + 0444 canonical manifest（文件集须恰好相等）；服务型 = `services/<id>.json`，只记身份、不记字节。
- **D4 交付** `staged`（只验证/发现/复用，缺则 `not-installed`）／`fetched`（坐标供规程用，APG 不下载）；服务型只能是 `staged`；**采集是非分发能力**，规程只写在采集工具里（非分发面）。
- **D5 四态** `available`/`degraded`/`not-installed`/**`conflict`**；单例冲突 fail-closed，不替你挑。
- **D6 权限** 发现/校验/健康 = 只读；起停/重启/排空 = Operator + 确认 + 世代校验。
- **D7 分发面（已修订）** 校验与发现契约上分发面（`lib/components.mjs` + `schemas/component-entry.schema.json`），**始终 85 文件**；digest 走 `9791c583…`→`3c935f4b…`（组件契约）→`f4d86ec0…`（路由词表）→**`e7f428d1…`**（消费者侧契约段）；采集器 `scripts/build-component-store.mjs` **不上**。
- **D8 服务条目判据**：health 路径必须用**只读 GET** 返回 identity；端点必须**免凭据**可达；进程必须能被信号终止；`degraded` 永不算 `available`。实测三件在跑的服务一条都不满足（`am` 的 GET 只有 liveness，identity 在 MCP 握手；`ee` 要 token；`ft` 只有 metrics 且忽略 SIGTERM）。
- **D9 身份可声明**：service 条目可带 `identity: {id_field, revision_field}`（缺省即 `id`/`revision`）；`asserted_identity: true` = 「在场但没人能核对是谁在应答」，**永远 `degraded`**；`identity` 与 `asserted_identity` **互斥**；`stop: signal|sigkill` 记录确定性停止。
- **D10 依赖可检查**：包与服务都可带 `requires`，只允许三种**单键**要求——`{component: <id>}`（`verify` 要求它真验证通过，`probe` 只要求它存在）、`{bin: <name>}`（`PATH` 上且可执行）、`{env: <NAME>}`（**只判存在，从不读取/记录/返回值**）。**任一不满足 ⇒ `degraded` 并附未满足清单**。包的要求写在 manifest 里，因此**被 digest 覆盖**。
- **D11 同一 id 两个 digest = `conflict`**：陈旧拷贝不得替组件回答问题，该 id 既不进 `reusable_packages` 也不进 `degraded_packages`，引用它的 requirement 不算满足；builder 只把残留报成 `stale` 并给**确切目录**，**自己不删**。
- **D12 第一条服务条目已写入且只能是 `degraded`**：`services/am.json`（见 §5）。D6/D8 的「没有写任何服务条目」到此成为历史。

## 5. 第一条服务条目（D12）

`~/.local/share/agent-project-guides/components/services/am.json`：

```json
{"asserted_identity":true,"delivery":"staged","endpoint":"127.0.0.1:18765","health":"/health",
 "id":"am","kind":"service","revision":"0.3.36","singleton":true,"stop":"signal","transport":"http"}
```

`identity` 与 `asserted_identity` 互斥，而 `am` 的 identity 只在 MCP 握手里 ⇒ 记录只能**断言**而不能核对，于是 `probe` 报
`probed: 1` 且该条目 `degraded`，**永不可能 `available`**，直到有组件愿意在只读 GET 里自报身份。`verify` 同时列出它
（`requires: []`、`revision: 0.3.36`），证明两个命令都看得见且都不改动它。（记录写入时 `am` 未运行，探测是 timeout→`degraded`，与 §4 第 2 条一致。）

## 6. 外部能力配置清单与新机器规程（plan §13.22）

- **清单**（谁要配什么、敏感度、APG 今天能不能检查）：`am` 无需凭证（身份只能断言）；`br`/`bv` 要 `.beads` 目录——**不能表达**；`cass` 要配套 CLI（已表达 `{bin:cass}`）与 **API key**（变量名无证据，**不猜**）；`ee` 要 `EE_SERVE_TOKEN`（**高敏感**，且与 D8「免凭据可探」冲突 ⇒ 不做可探服务）；`ft` 要 WezTerm mux（已表达 `{bin:wezterm}`，服务侧 `stop: sigkill`）；`ntm` 要 tmux（已表达 `{bin:tmux}`）；`sbh` 要 **daemon + root**（**高敏感**、不能表达）；`slb` 要项目初始化——**不能表达**。
- **规程**（只有采集是非分发能力）：按记录核 sha256 → 同一目录暂存（保持 `asset.name`）→ `--dry-run`（`record_mismatch` 必须为空）→ 真跑 → `apg components verify`（`missing_packages` 必须为空；`degraded_packages` 是「本机缺它声明的前置条件」）→ `apg components probe`。规程写在 `scripts/build-component-store.mjs` 头注释里并由 `--help` 打印同一份；消费者侧边界写进分发的 `docs/V2_CONTRACT.md`（机器本地、只读、`present:false` 不是错误、铺库不属于分发能力）。

## 7. 实测与重算改掉的四处真缺陷

1. `verify`/`probe` 同名裸 `reusable` 指两个域（`878f8d9`）。
2. 「200 但没有身份」曾报成 `the endpoint belongs to undefined` → 现在 `conflict` 并点名缺什么（`878f8d9`）。
3. **要求检查一度到不了 CLI 判决**：`requires` 在 manifest 里而 store 遍历只返回 `{kind,id,digest}` ⇒ 修复后遍历读回 `requires` 并重跑门禁（`a39c5a2`）。
4. **同一 id 两个 digest 仍报可复用**：重算 manifest 后 `cass`/`ft`/`ntm` 换 digest，旧目录留下且摘要列两次 ⇒ 现在判 `conflict`、builder 报 `stale` 只给目录不删，三个陈旧目录已按显式名字删除（`a39c5a2`）。

门禁 `scripts/test-component-store.mjs`：**55 → 64 → 103 → 118 条断言**（静态计数）。三条反证都跑过：短路
`applyRequirements` 降级分支 ⇒ 红在 `expected: 'degraded'`；撤掉 maintainer 的新增中文名词 ⇒ `test-v2` 红在
