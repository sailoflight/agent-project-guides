# 外部根指令写入方普查（11 个写入方）与 APG 守卫覆盖

**日期**：2026-09-20 ｜ **范围**：`.agent-scratch/external-test/repos/` 的 39 个外部 checkout ｜ **发布落点**：APG 3.0.10

这份普查的用途只有一个：**回答"APG 对根指令文件（`AGENTS.md` / `CLAUDE.md`）的所有权主张，在真实世界里成立吗"**。结论分两半——写入方比原先记录的多得多（3 → 11），而守卫的 marker 文法缺了其中 3 个真实形态；两半都已闭合。

## 1. 写入方普查结果

- **11 个组件带根指令写入方**，**28 个组件经复核确认没有**（字面量 grep + 写 API 站点复核，边界=所列扩展名与路径）。
- 原始证据：`.agent-scratch/external-verify/census.json`（17 条写入记录、51 条语法结果）+ `evidence/`（含 SHA256SUMS）。证据的生命周期：`.agent-scratch/external-test/repos/` 被删除时同步失效；点名删除 `.agent-scratch/external-verify`。
- 完整写入方表（marker 字面量、备份约定、递归/前置条件、证据来源 `scan` vs `scan+real-run`）已落在 `decisions/0006-root-instruction-block-ownership.md` 的 "Writer survey: the full census" 一节。

**11 个写入方**：`br`(beads_rust)、`bv`(beads_viewer)、`ee`(eidetic_engine_cli)、`slb`、`sbh`(storage_ballast_helper)、`frankenterm`、`am`(mcp_agent_mail_rust)、`ubs`(ultimate_bug_scanner)、`cass`(cass_memory_system)、`ntm`、`acfs`(agentic_coding_flywheel_setup)。

## 2. 三条改变判断的发现

1. **`ubs` 的"有备份"只在第一次成立**：`install.sh:4007` 的 `cp` 早于 `:4012` 的"已存在"检查，幂等重跑会用**已修改后**的内容覆盖原始备份（实测 sha `142c1e29…`(36 B) → `9b49d91a…`(2147 B)）。⇒ 对 APG 的含义：**不能把"对方有备份"当作恢复点依赖**，APG 自备份（P8）必需而非冗余。
2. **`ntm` / `acfs` / `cass` 是整文件改写型**（`ntm` 的块边界是 `<INSTRUCTIONS>`，无 HTML 注释；`acfs` 真跑 `--output` 把 39 B 人工文件整文件覆盖为 4244 B 且无备份）。⇒ **marker 守卫不可能完全防住整文件改写方**；只保护 APG 的**插入**不搬移他人区域，改写在 APG 之后发生时只有 `install.sh check` 的漂移检测能发现。这是一条**能力边界**，已写进 ADR 0006 的 open items。
3. **`bv` 的 marker 版本号是数据**（代码发 `v7`，现场有 `v1`×31、`v5`×1）⇒ 文法**只能钉形状，不能钉版本号**。

## 3. 守卫文法的四个真缺口与一类过度匹配（已闭合）

现场扫描 39 个根指令文件的 78 条注释行：**写入方发出的 start marker 100% 命中（37/37）**，但系统普查另找到 **3 个此前不可见的真实写入方形态**：

| 字面量 | 写入方 | 旧文法 | 新文法 |
|---|---|---|---|
| `<!-- Auto-generated rules from cass-memory playbook -->` | `cass` | allow（**漏**） | refuse |
| `<project_rules>` / `</project_rules>` | `cass` | allow（**漏**） | refuse |
| `<INSTRUCTIONS>` / `</INSTRUCTIONS>` | `ntm` | allow（**漏**） | refuse |
| `<!-- >>> -->`（空箭头） | 无（合成探针） | refuse（**误拒**） | allow |

实现：`FOREIGN_COMMENT_MARKER` 增加 `auto-generated\b`；新增**区分大小写**的 `FOREIGN_TAG_MARKER`（全大写 tag 或 snake_case tag，且必须独占一行）；`>>>`/`<<<` 分支要求箭头后有真实文本。

**回归落点**：`scripts/test-install.sh` 的 P3 词表 = **32 行（14 refuse / 18 allow）**，其中 7 条是**现场扫到的"无写入方"字面量**、5 条是"永不命中"形态 ⇒ **两个方向都钉住**。负向验证：回退到 pass-2 文法，上表四条同时失败。

## 4. 刻意**不**做的泛化（与已裁定的窄口径一致）

现场存在两种 marker 形态**没有任何写入方**：`-<word>-v{n}` 族（`casr`、`dcg` 的文档小节标题）与 `<!-- BEGIN <NAME> -->`（本机 `~/.codex/AGENTS.md` 的人工分节，2403 B）。它们都是**人工提交**（已核对全仓无写它们的代码），纳入文法就是为人工注释拒绝迁移。故只记录证据，不动文法；`test-install.sh` 的 `allow` 行把这条边界钉死。

## 5. 本机"安装面"扩展扫描（有没有第 12 个写入方）

PATH 上只有 `claude`、`codex` 两个外部 CLI；`~/.claude` 下无 `CLAUDE.md`；`~/.codex/AGENTS.md` 是人工个人规则；**无** `~/AGENTS.md`、**无** `~/code/AGENTS.md` ⇒ 13 个消费者仓之上**没有父亲目录继承面**，APG 的 byte-0 所有权假设在本机不被继承规则破坏；APG marker 只出现在 codex 的 session 转录里，不在任何指令文件里。⇒ **本机无未记录的第 12 个写入方**。

## 6. 未验证的（明确不确定性）

本机**无 go、无 cargo/rustc、无 bun** ⇒ `bv`/`slb`/`sbh`/`am`/`ntm`/`ee`/`frankenterm`/`meta_skill`/`cass` **未真跑**，其语义全部来自源码阅读；`ubs` 的真跑是"逐字抽取写入函数"而非上游入口（上游唯一入口会下载二进制、改 rc、装 cron，按红线不执行）；`pi_agent_rust` 的写入方位于 vendored fixtures，未被上游 CI 真实使用未验证。
