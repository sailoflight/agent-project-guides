# APG 根指令文件：写入方普查、块所有权与引导块完整性（3.0.9 最终态）

**这是派生路由件，不是权威源。** 权威顺序：`decisions/0006-root-instruction-block-ownership.md`（块所有权协议）→ `plans/MULTI_AGENT_INFRA_INTEGRATION_RESEARCH.md`（§13.9–§13.12 取证与实测）→ 仓内代码与测试。冲突时以仓内为准。

本文覆盖 3.0.9 之前若干派生快照已过时的三处：写入方是 **5 个不是 3 个**、P3 已闭合（不是未做）、schema-1 引导块残余**已闭合**（不是仍未闭合）、APG 自身块是 **2,062 B**（不是 1,706 B）。

## 1. 写入方实测：5 个（原记 3 个）

一次覆盖 39 个外部 checkout 的普查（`.agent-scratch/external-test/repos/`，非 git 区）得到以下结论。所有结论都来自读源码，不是推断。

| 写入方 | 标记 | 改前备份 | 关键行为 |
|---|---|---|---|
| APG | `agent-project-guides:routing:start\|end`、`adapter-trigger:start\|end`、`v2:start\|end` | 有（P8，后缀 `.agent-project-guides.bak`） | 占用根文件**字节 0**（`scripts/install.sh` 断言）；`manage-root-blocks.mjs` 是 marker 级 `strip`/`replace`，保留非自己拥有的每一个字节 |
| `br`（beads_rust） | `br-agent-instructions-v1`（版本在标记里），前缀匹配识别 | 有，`<file>.md.bak` | 追加式；向上找最近的 `.git`/`.beads`/`_beads` 作项目根 |
| `ee`（eidetic_engine） | `ee:agentsmd:begin generation=N hash=H` / `ee:agentsmd:end` | 有，`.ee-backup` | 唯一把内容哈希写进自己标记的写入方；手工改块以 `agentsmd_unmanaged_edit_detected` 拒绝 |
| `am`（mcp_agent_mail_rust） | `<!-- am:blurb -->` / `<!-- am:blurb:end -->`，**无版本 token** | **无** | 裸 `std::fs::write`；对**任何** `.md` 填充孤立的 `am:blurb` 起始标记；对**无标记**的 `AGENTS.md`/`CLAUDE.md` 追加整块；**默认递归 3 层**。风险最高的写入方 |
| `ubs`（ultimate_bug_scanner） | `<!-- >>> Ultimate Bug Scanner quick reference (written by install.sh; removed by install.sh --uninstall) -->` / `<!-- <<< End Ultimate Bug Scanner quick reference -->` | 有，`.backup` | **非命名空间**注释，靠内容 grep 识别；仅在 `AGENTS.md` 已存在时写 |

**两处旧记录被实测推翻**：`bv`（beads_viewer）改 `AGENTS.md` 前**不备份**（原子 `os.Rename`；`--rollback` 是它**自升级**的路径，不是文件回滚）；`ntm` 写 `AGENTS.md` **完全不带标记**（整文件模板，且只在文件不存在时写）——marker 式所有权看不见它。

**因此「外部写入方都会备份」是错的**：5 个里有 2 个不备份，且存在 3 种互不相同的备份后缀（`.md.bak` / `.ee-backup` / `.backup`）。任何依赖「改前一定有恢复点」的假设都只对 APG 自己成立（P8）。

## 2. P3：拒绝搬移别人的块（口径经主人收窄）

- **收窄口径**：只有当**其他写入方的受管 marker 块**（命名空间非 `agent-project-guides`）位于 APG 区域**之上**时才拒绝并请人工 reconcile；**项目自撰正文仍照旧迁移**（pre-scheme-1 尾置布局，`scripts/test-install.sh` 有意断言它成功）。ADR 原文「之上有任何内容就 fail」与既有测试不能同时成立。
- **实现**：`scripts/manage-root-blocks.mjs` 的 `guard-prefix` 原语，由 `scripts/install.sh` 的 `rebuild_root_prefix` 在 strip 之前调用；拒绝时不落盘。
- **已记录的边界**：guard 只在 APG 区域**已存在**时生效。根上还没有 APG 区域时仍按 P1 抢占字节 0，把既有内容整体下移（字节与顺序无损）——那是前缀保留，不是搬移外部块。
- **文法必须覆盖实测词汇**：第一版文法基于 `br`/`bv`/`ee`，认不出 `am` 的 `:blurb` 与 `ubs` 的 `>>>`/`<<<`，这两个写入方的块落在前缀之上时**仍会被静默搬移**。现覆盖全部 10 种实测形态，同时放行项目正文、APG 自己的 integrity 行、markdownlint 的 `<!-- end list -->`、`<!-- TODO: end -->` 与版权注释。
- **非空证明**：把文法回退到第一版会使 `scripts/test-install.sh` 以 `FAIL: P3: guard did not recognise the am foreign marker block` 失败；该套件用 15 行对照表把 10 种必须拒绝 / 5 种必须放行的形态固定下来。

## 3. 受管块完整性：P9 + schema-1 锚（残余已闭合）

**块内行（P9）**：`<!-- agent-project-guides:integrity sha256=<hex> -->` 是受管块的**第二行**，所以起始标记仍是第 1 行、字节 0 不变，`sed` 区间提取与「恰好一次」断言继续成立。`manage-root-blocks.mjs` 提供 `stamp`/`verify`/`replace`；逃生开关 `AGENT_PROJECT_GUIDES_FORCE_MANAGED_BLOCK=1`。override 语义与 `ee` 刻意不同：APG 的块承载**活的适配状态**，更新路径复用已装块而非重渲染，带 override 是「接受并重新背书」。

**描述符侧锚（schema 1，闭合残余）**：块**内部**的 hash 挡不住能改整个文件的写入方——改正文的人顺手就改记录行。因此 schema 1 增加了 schema 2 早已有的字段：

- `integrity.root_block_hash` 是 `schemas/project.schema.json` 的受校验字段（`lib/descriptor.mjs` 做 exact-keys + sha256 格式校验）；哈希口径与 schema 2 **完全一致**：对 marker 区间内的块字节取 sha256。
- `project init` 记录它；`project reattest` 刷新它。
- `lib/bootstrap.mjs` 的 `inspectBootstrap` 比对它，并且**两个锚都没有的块以 `bootstrap_unverifiable` 拒绝**——不再有「当作 legacy 放过」这条路（这正是 `finding.h1.bootstrap-token-only-validation` 的残余）。
- `project validate` 追加报告 `bootstrap.anchor` ∈ `block` | `descriptor` | `both`，以及 `bootstrap.root_block_hash`。
- 字段本身在 schema 里是**可选**的（旧的描述符仍可读），不可选的是「块必须能被某个锚验证」。

**证据（`scripts/test-v2.mjs`）**：保留三个 token 的篡改 → `bootstrap_mismatch`；删掉 integrity 行 → 因描述符锚而 `bootstrap_mismatch`；连描述符锚一起删 → `bootstrap_unverifiable`。

## 4. `project reattest` 与升版流程（实测步骤）

**为什么需要它**：锚是「一个会合法变化的块」的哈希——块渲染了 pin 的 release 与 digest，所以升版按设计就会让记录的锚失效；而手改描述符正是锚要防的那种未经校验的编辑。

**语义**：先校验**已装**块（字节 0、恰好一对 marker、块内 integrity 行），所以它不能把手改洗白成新锚；它**有意容忍**描述符 token 不匹配（那正是要修的状态）；运行根经 `openProvider` 解析，因此 source-worktree / thin-bootstrap / embedded-local 都可用；**先装块、后写描述符**，中间崩溃会被 gate 发现，重跑即可收敛；幂等。回执含 `previous_integrity` 与 `previous_descriptor_anchor`（`absent` | `matched` | `stale`）。

**升版步骤（3.0.9 实跑过）**：

1. 改 `PACKAGE_VERSION`；
2. **同步** `.agent-project-guides.json` 的 `provider.release`（source-worktree 模式强制两者相等，`lib/descriptor.mjs`，否则描述符校验直接失败）；
3. `node scripts/apg.mjs project reattest --target .`（重渲染根块 + 记录新锚）；
4. `node scripts/apg.mjs release manifest`（重建 `PACKAGE_MANIFEST.json`）；
5. 门禁：`catalog check` / `scripts/validate-routing.mjs` / `release verify-source` / `project validate --target .` / 相关 `test-*.sh`。

**不要手改描述符或根块。** README 里出现版本号的三处也要同步（`scripts/test-install.sh` 对 README 有 12,000 字节硬上限）。

**`provider import` 的坑（已修）**：锚是**本地安装事实**、不是可移植项目事实（`portableSnapshot` 正确地不含它），所以导入快照必须**保留本地锚**，不能把「快照里没有」读成「要应用的变更」。

## 5. 决策 7 / 8：拍板建议（**待签字，尚未生效**）

**命名空间（决策 7）**：`agent-project-guides:external:<command-name>`。

- `<command-name>` = 二进制的**调用名**，不是仓库目录名（实测 `ee`、`cass`、`sbh`、`cm` 都与仓库名不一致）。
- **版本作字段、不进命名空间段**：实测一个工具跨三个标记版本（`beads_viewer` 代码发 v7、自己 README 是 v7、自己 AGENTS.md 是 v5，而 39 个 checkout 中 31 个仍是 v1）。
- **完整性作三元组** `{state, algo, digest, scope}`，不是裸 hex。
- 命名空间按**词法定界**匹配（`br`/`bv` 都是前缀匹配自己的名字；`.cass/` 已被两个互不相关的组件同时占用）。

**EE trust 映射（决策 8）**：**只做注意力排序，永不作为权威输入。**

- 阶梯是固定先验表（`eidetic_engine_cli/src/models/trust.rs` 的 `initial_confidence()`：0.85 `human_explicit` / 0.75 `peer_human_attested` / 0.65 `agent_validated` / 0.50 `agent_assertion` / 0.45 `cass_evidence` / 0.30 `legacy_import`）。
- 最高档是 `ee remember` 的**默认值**（`src/core/memory.rs`，除「已注册 agent 身份的 attempt-family 写入」外一律落 `human_explicit`），无 flag/TTY/签名门槛；可经 MCP `allowWrite=true` 到达；可经调用方自填的 `--source-type human_explicit` 提升（`src/core/outcome.rs` 的准入只有「非空 actor + 非空 reason」），而严格校验器 `validate_trust_promotion_evidence`（`src/policy/mod.rs`）**不在那条路径上**。
- 唯一有认证入口的 `peer_human_attested` 被排除在写入白名单外；能把等级翻成权威的构造在生产代码里**零调用点**。
- 映射建议：4 档 → `intended`；`peer_human_attested` 只映射「EE 声明了该等级」这件事本身（映射对象是声明，不是等级为真）。建议新增术语 **`declaration-observed`**（宿主上真实观测到某外部系统声明了 X，但 X 未验证）——**进正式词表需主人签字**。
- EE 内部**至少 4 套互不兼容的数值阶梯**（trust 先验、ask tilt、pack rank、hotset），所以引用等级**必须同时写明 scale 名**，否则数字不可解释。

## 6. 仍未闭合 / 已批准未实施

- **P6**：观测账本未实现——没有任何记录「APG 见到过哪些外部块」的地方。
- **P7**：APG 自身块 2,062 B，消费者用 731–758 B。
- **已批准未实施**：组织原则 ADR（报告 §10.4 + §11 三条决定）；决策 4「`docs/memory` 让 catalog 也按目录跳过」（与 `lib/core.mjs` 的 `DIST_EXCLUDED_DIRS` 对齐）。
- **一处已披露的代价**：任何描述符编辑都会改变 `projectDigest`（= `sha256(canonicalJson(descriptor))`），使 `docs/memory` 里已晋升记录内嵌的锚变旧。3.0.9 的编辑把它从 16/18 扩大到 18/18。修法（把并发 CAS 与历史溯源分开）属放宽完整性约束，需架构负责人拍板，见 `docs/memory/finding.m1.memory-supersede-anchor-frozen-by-descriptor-drift.json`。
- **分发面约定**：`CHANGELOG.md` 在仓库根、**刻意不进分发面**（`lib/core.mjs` 的 `DIST_DIRS`/`DIST_FILES`/`SCRIPT_FILES` 之外），因此也不进 catalog——catalog 是路由语料，版本章节在那里只是噪音。`decisions/`、`plans/`、`fixtures/`、`scripts/test-*` 同样不发行。
