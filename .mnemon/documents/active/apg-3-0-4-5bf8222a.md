# APG 3.0.7 精简发布与九仓库消费者部署记录（3.0.4→3.0.7）

用户要求："尽量不输出 sha256、仅用必需字段与 AI 交流"，追加优化、提交并部署到其他仓库；随后现场暴露沙箱写失败，再两次要求缩短票据（57→30→19 字符，认证码最终定为 64 位）。设计根因见 apg-context-generation-ed071bbb；本文是发布/部署轨迹的现行权威记录（已取代旧的"3.0.4 八仓库"与"3.0.6"记录）。

## 版本轨迹（均已推送 origin/main）
- `e218c47` 3.0.4：默认 compact 文本；shared 澄清用 35 字符 `g1_<32hex>` 引用 + 私有安装状态 `generation-handles/` 存完整签名 generation；诊断仅 `--format json`。
- `6611d26` 3.0.4 补充：压缩 procedures/PACKAGE_ADAPTATION.md、profiles/MONOREPO_PROJECT.md；readapt 路由 ids 置空但完整适配流程仍载入；消费者 4096 预算不变；全套路由矩阵入预算。
- `60ff70c` 3.0.5：**g1_ 私库写入在 DSH workspace-write 沙箱外失败**（用户 pythonpubliclib 现场 `generation_reference_write_failed`）→ 改为 57 字符无状态 `g2_` 票据（8B 毫秒过期 + 完整 32B HMAC，绑定描述符+真实项目路径+唯一候选），签发/续接零写入；环境/key 错误提示停止并报告（不再引导重试/找 token）；旧 g1_ 仍可读。实测：禁写 Node `--permission --allow-fs-read=*` 下澄清+续接正常。
- `e149f7c` 3.0.6：票据缩到 30 字符 `g3_`（4B Unix 秒过期 + 16B HMAC-SHA256 截断；128-bit 认证，域含版本防跨格式重释）；旧 g2_/g1_ 兼容读取。
- `560bd8f` 3.0.7：**票据缩到 19 字符 `g4_`（4B Unix 秒过期 + 8B HMAC-SHA256 截断，64-bit 认证码；用户对 128-bit 提出疑问后明确选定 64 位）**。64-bit 适用于本机短时、不授予权限的治理路由，防伪强度低于 g3/g2；若未来用于远程或真授权须重新评估。旧 g1_/g2_/g3_ 兼容读取；截短旧票据冒充 g4 被拒。

## 部署（受支持可回滚迁移路径，每仓库）
备份原像（字节+权限+git status）→ 隔离副本 `rollbackV3Migration` + `previewV2ToV3Migration`/`applyV2ToV3Migration` → 现场 rollback→preview→apply → `project validate` 18 路由 + 禁写 Node 下的 context 澄清与 g4_ 续接验证。管理块外项目指令逐字节保留（win-wsl-mcp-bridge 曾因 AGENTS.md 指令漂移需先按迁移回执恢复原像再回滚，后回填保留）。

九仓库全部 **3.0.7**：CadQ、cc_switch_tiny_switch、cc-teamwatch、dsh-bash-escalation、dsh-bench、dsh-vision-toolkit-windows-edge、onshapescript、taobao-mcp、win-wsl-mcp-bridge。现场 compact 澄清约 557–665 B（g4 后更小）。改动仅 .agent-project-guides.json、AGENTS.md managed 块、.agent-guides/{MANIFEST.json,ROUTES.jsonl} 与共享 launcher；业务代码/服务/模型路由未动。消费者 Git 状态集合与部署前一致、暂存区为空。
