# APG 消费者上下文预算、指导文档瘦身与建议箱机制交接

相关文档：通用性审查与清理见 `4fceda3f`（APG 3.0.7 通用性审查及清理）；提交轨迹见 `5bf8222a`。本文件覆盖其后的**预算测量 → 两轮瘦身 → 建议箱机制 → 路由文档语言统一**阶段。

## 1. 什么会进入消费者上下文

- **bootstrap 注入块**（常驻消费者根指令文件）：`bootstrap/AGENTS.v2-block.md`、`bootstrap/AGENTS.routing-block.md`、`bootstrap/AGENTS.adapter-trigger.md`、`bootstrap/CLAUDE.scope-block.md`。
- **按 route 加载的 catalog 源**：角色分节（`roles/*`）+ facet profile 分节（`profiles/*`）+ overlay（`profiles/overlays/*`）+ 模式 procedure（`procedures/*`，仅 `initialize`/`readapt` 加载）。
- **两层预算**：route token 预算在 `routing/context-routes.jsonl`（每 subject 一个 `budget`）；bootstrap 字节预算在 `scripts/test-install.sh`（routing-block ≤2000、adapter-trigger ≤3000、CLAUDE ≤500、README ≤12000、DEVELOPER ≤4000、PACKAGE_ADAPTATION ≤9500、MCP ≤5500、WSL_BRIDGE ≤8500）。
- token 估算统一 `utf8-bytes/4-ceiling`；`validateContextRoutes` 在每次 context/resolve 时校验，超出即失败（test-v2 覆盖）。

### 测量方法（含一个坑）

- 各 subject 用量/余量：遍历 `routing/context-routes.jsonl` 的 `default`/`by_mode.ids`，从 `catalog/catalog.jsonl` 取每 ID 的 `tokens` 求和，与 `budget` 相减。
- **坑**：预算断言写作 `wc -c < FILE | tr -d '[:space:]'`——管道先 `wc` 后 `tr`，比较的是**原始字节数**（约 11.5KB 的 README 曾只剩 6 字节余量），不是去空白后的字节数。测量必须用同一管道。

## 2. 基线压力与两轮瘦身结果

**基线**：22 个活跃 subject 中 21 个用量达 88–99%（maintainer[code] 1281/1300、verifier 444/460、operator 442/460、reviewer 461/480 与 557/580、user 308/330、developer 623/650、content-package 272/290…），overlay 各余 11–13；routing-block 1977/2000（余 23B）、adapter-trigger 2871/3000（余 129B）。结论：文档顶死预算，任何措辞微调都会破坏校验。

**第一轮（引导常驻 + 角色/overlay，12 文件，净 −1074B）**：MAINTAINER 5569→5241（余量 19→74）、OPERATOR 2450→2244（18→70）、REVIEWER 2562→2464（19/23→44/48）、USER 1724→1646（22→41）、DEVELOPER 3185→3120（27→44）、FIELD_EVALUATOR 3066→3024（21/22→31/32）、VERIFIER 1840→1796（16→26）、routing-block 1977→1869（23→131B）、adapter-trigger 2871→2824（129→176B）、3 overlay 合计 −58B（11/13/13→16/21/15）。

**第二轮（profile，6 文件）**：cli 24→48、mcp 30→46、library 28→42、application-ui 22→28、service 24→26、data-automation 26→27（tokens）。MONOREPO 余量 132、CONTENT_PACKAGE 已极简，未动。

**当前最紧余量**：research-reproducibility overlay 15、agent-governance 16、content-package 18、mechanical-modeling 21、verifier 26（均为 tokens）。此后已无 90%+ 压力点。建议箱新增一行使 maintainer[code] 回到 1256/1300（余 44）。

### 瘦身铁律（后续必须同样遵守）

1. **不得改动 `##` 标题文字**——route section ID 是标题 slug（如 `role:development/maintainer#4-bug-和回归处理`），改名即破坏 `routing/context-routes.jsonl` 与全部路由测试。
2. **保留 `scripts/test-install.sh` 的全部内容断言字符串**（routing-block 9 条、adapter-trigger 10 条、CLAUDE 2 条、MCP/README/PACKAGE_ADAPTATION/模板若干）。
3. 只压措辞，不删除规范性规则、权限边界与禁止事项（“不要 X”可压成“不 X”，但规则语义不得丢失）。
4. 不得引入任何客户端词（`scripts/test-genericity.mjs` 失败）。
5. 内容改动后必须重生成派生物：`catalog build` → `catalog check` → `release manifest`（否则 `validateSourceCatalog`/`release verify-source` 失败）。

## 3. 建议箱机制 v1（本阶段新增能力，未提交）

- **写信侧**（所有消费者 agent，经 `bootstrap/AGENTS.v2-block.md` step 3 生效）：clarification 选项无一适配 / 路由角色与工作不符 / 角色或 mode 不够用时，**先在最近允许的路由下完成任务**，之后按 `templates/SUGGESTION_BOX.md` 格式写一封信到 `.agent-project-guides/local/suggestions/NNNN-<type>-<slug>.md`（clone-local，APG 工具永不自动 stage/commit/传输）。
- **信件格式**：`Type: missing-role | wrong-role | missing-mode | routing-gap | other` + 尝试路由 + 任务/证据/最小改动建议/影响面；单信 ≤2KB、单信一事、禁秘密与文件转储、`NNNN` 取目录内下一个未用编号。
- **处理侧三层**：① Package Re-adapter（initialize/readapt，`procedures/PACKAGE_ADAPTATION.md` §8）：适配完成前计数/分类入适配报告，可行项转 `proposal`；② Maintainer（`roles/development/MAINTAINER.md` §3）：会话起点见未处理信件先分诊，处理后移入 `processed/` 并留一行结论；③ APG 源仓维护者：需改包的信件随消费者更新报告进入 APG 仓库自己的信箱，走正常维护周期。
- **权限边界**：信件是 report-only 输入，不授权、不直接改路由；与“角色声明不能制造权限”同构；永不从信件自动实施新角色。
- **v1 范围**：纯引导层约定（prompt-level），无工具命令。可选 proposal：`install.sh suggestions list/triage`、APG 仓库根建实际信箱目录并纳入维护例程。
- **测试**：`scripts/test-install.sh` 新增 4 条断言（v2-block 含箱路径、模板存在、Type 枚举行、procedure 含 `local/suggestions`）。v2-block 1725→1969B，新模板 1797B。

## 4. 语言统一与遗留决策

- **审计结论**：`roles/`+`procedures/` 中文主导（含协议标识符）；`profiles/`+`overlays/`+`templates/`+`docs/`+`bootstrap/` 纯英文，文档内自洽。真正“文档内混排”3 处：`roles/production/OPERATOR.md`（整段英文模式说明）、`procedures/PACKAGE_ADAPTATION.md`（英文标签/表头）、`profiles/mcp/WINDOWS_WSL_BRIDGE.md`（中英均衡，最严重）。
- **本轮处理**：三处按主导语言统一为中文；技术标识符原样保留（MCP/Facade/Engine/prompt/initialize/tools-list/schema/revision/dry-run 等）。WSL 桥接从 1030CJK/405EN 均衡 → 中文主导，7448→7349B；3 条中文断言与全部标题未动。
- **遗留决策（待用户定）**：跨文档双语分工仍在——消费者每次 route 的实际体验是“中文角色文档 + 英文 profile/overlay 分节”。彻底统一需翻译 8 profile + 3 overlay（约 12KB），并同步更新 2 条英文测试断言（MCP profile 的 `one bounded canonical runtime prompt`、`Tool descriptions alone do not pass.`），逐 route 复验预算（中译后 token 大致持平或略降）。维持双语分工（执行面中文/契约面英文）亦为合理选择。
