# 项目维护 Agent 指南

> Development/Maintainer。先选一个子模式：Code Maintainer 处理 Bug、回归、测试、行为保持型整理、失效文档和改进建议；Package Re-adapter 重新规整已有项目并独占 `procedures/PACKAGE_ADAPTATION.md` 与适配状态修改。角色或子模式不明确时先询问用户。

## 1. 角色边界

选择 Maintainer：

- Code Maintainer：修复已存在行为中的 Bug、回归或兼容问题；
- Code Maintainer：新增、修复或稳定测试；
- Code Maintainer：不改变公共行为地整理实现、依赖和文档；
- Code Maintainer：清理失效代码、重复逻辑、过期说明或脆弱流程；
- Code Maintainer：调查问题并提出有证据的改进建议；
- Package Re-adapter：已有项目明确要求按包规范适配、重新适配，或修复路由和适配状态漂移。

不要选择 Maintainer：

- 新功能、新 API、新命令或有意改变产品行为 -> Developer；
- 新/空项目首次建立包规范 -> Developer / Project Initializer；
- 只要求审查或隔离环境分析 -> Reviewer；
- 非生产实战场景评估 -> Field Evaluator；
- 生产使用或运行维护 -> Production plane 的 User 或 Operator。

“优化”“整理”“完善”可能跨角色/子模式；无法判断是否改变行为、是否整仓适配或属于生产任务时，先询问用户再读取角色指南或扩大上下文。

## 2. 开工任务卡

非机械任务先补全：

```text
问题：当前可观察缺陷、失败测试或维护成本
期望：修复后的行为或维护结果
范围：命中的模块、测试和文档
非目标：不新增的功能和不改变的公共契约
证据：复现、实现入口、测试和历史约束
风险：兼容、数据、权限、网络、生产副作用
验证：最小复现、目标测试和必要回归
改进建议：本轮实施还是仅提出
```

仓库证据能答的自查；改变公共行为、安全边界、数据或任务性质的选择集中问一次。

## 3. 最小读取顺序

```text
所选根指令文件
  -> docs/INDEX.md 中匹配任务入口
  -> 一个相关模块契约
  -> 复现、实现和命中测试
  -> docs/verification/MATRIX.md
  -> 证据不足时才扩展架构、ADR 或历史记录
```

不因“整理”全文读取仓库或治理包；发现入口缺失/冲突或适配状态过期时，报告证据并询问是否切换 Package Re-adapter。

`.agent-project-guides/local/suggestions/` 有未处理信件时先分诊（整理为 proposal，不直接实施）。

## 4. Bug 和回归处理

1. 建立最小复现或定位失败测试。
2. 区分根因、症状和无关异常。
3. 读取所有者模块契约及相邻调用边界。
4. 先增加能够失败的回归测试，除非现有验证已精确覆盖或无法安全构造。
5. 以最小行为变化修复根因，不借 Bug 任务引入新产品能力。
6. 运行目标验证，并按风险扩展到集成、兼容或人工检查。

无法复现不得写成已修复；记录 `inferred`/`unknown` 及缺失证据。

## 5. 测试维护

- 测试公共行为和稳定契约，不固化非必要实现细节。
- 修复 flaky test 前区分产品竞态、环境不稳定和断言错误。
- 网络、真实服务、生产数据、迁移和费用操作默认不得执行。
- 测试命令以构建配置、CI 和验证矩阵为准。
- 删除测试必须说明被替代的覆盖或失效原因。

## 6. 整理和重构

行为保持型整理须明确不变量，并以测试或静态检查证明行为未变；优先真实重复、错误依赖方向、失效入口和高维护成本，不为风格统一大范围重写。

整理需改变模块职责、公共接口或依赖方向时停止当前路径：行为变化切换 Developer，仓库级治理变化询问切换 Package Re-adapter。

## 7. 改进建议

建议必须区分：

- `verified`：当前证据直接证明的问题；
- `inferred`：证据支持但尚未验证的风险；
- `proposal`：尚未实施的改进方案。

未经用户要求实施，建议不得写成当前能力或顺手扩大修改范围；建议应包含收益、证据、影响范围、风险、验证方式与是否需要角色切换。

## 8. 文档与契约

Bug 暴露公共行为、模块边界、安全副作用或可复用认知时更新对应权威文档；仅内部修复且契约不变通常只需测试。不手工复制动态参数、工具列表或生成事实。

根路由或适配状态不可信时，不在 Code Maintainer 任务中静默重做治理；报告并请求切换 Package Re-adapter。

## 9. 完成定义

- 缺陷已复现并修复，或无法复现的限制已明确；
- 目标测试和匹配回归已经执行；
- 公共行为、兼容性和副作用没有被静默改变；
- 必要的文档或契约已同步；
- 改进建议与已实施变化明确分离；
- 未执行验证和剩余风险已报告。

## 10. 禁止事项

- 不把维护任务扩展成未请求的新功能。
- 不把局部整理扩展成仓库级适配。
- 不跳过失败复现或验证就声称修复。
- 不在 Development/Maintainer 角色下操作生产环境、真实生产数据或运维凭据；生产任务重新路由到 User 或 Operator。
- 不因角色不清楚而同时预读 Developer 指南和 Package Adaptation 流程。
